# Lab 5 — Agent evaluation in the Portal (15 min)

## Goal

Evaluate `contoso-travel-assistant` end to end in Microsoft Foundry Portal using
the synthetic test data registered by Lab 1's Deployment Scripts.

Run the same question set against the agent built through Lab 4 and
**identify improvements from its answers and tool use**.

The answering agent and the scoring model have different roles.
This workshop uses `gpt-5.6-luna` for the agent and `gpt-5.5` for configurable LLM judges.

> [!WARNING]
> Agent invocation and LLM evaluators incur charges.
> This lab is limited to 7 synthetic cases.

Use the agent saved through Lab 4, including MCP auto-approval settings.

## 1. Create an Evaluation

1. In the project's left navigation, open **Build > Evaluations**.
2. Select **Create**.
3. Set **Target** to **Agent** and select the `contoso-travel-assistant` row on the right.
   Do not select Hosted Agent or Model.
4. In **Version**, select **exactly one** latest version containing the saved Lab 4 changes.
5. Verify the agent and version, then select **Next**.
6. Set **Scope** to **Individual turns**, then **Next**.
7. Set **Frequency** to **One time**, then **Next**. Do not schedule recurring runs.

## 2. Select the synthetic dataset

1. Under **Data**, select **Existing dataset**.
2. Select `contoso-travel-eval-live-subset`, then **Next**.

This fictional dataset was registered from `data/eval/live_subset.jsonl` by Lab 1's Python adapter.
Use the 7 registered cases without generating new data.

## 3. Set Field mapping

**Field mapping** assigns dataset columns (`item.*`) and outputs obtained from the agent
during evaluation (`sample.*`) to standard evaluator fields.

1. In Lab 1's deployment **Outputs > resourceOutputs**, verify
   `evaluation_model_deployment_name.value` is `gpt-5.5`.
2. For **Judge model**, select **Deployments > gpt-5.5**.
   Change it if `gpt-5.6-luna` is selected initially. If `gpt-5.5` is missing,
   ask the administrator to check Lab 1's model deployment before continuing.
3. Verify:

| Field | Mapping | Meaning |
|---|---|---|
| **Query** | `{{item.query}}` | Question stored in the dataset |
| **Response** | `{{sample.output_text}}` | Final answer generated by the agent in this run |
| **Context** | **Not available** | Leave unchanged; this dataset has no fixed `context` column |
| **Ground truth** | `{{item.ground_truth}}` | Expected answer for rows with reference answers |
| **Tool calls** | `{{sample.tool_calls}}` | Tool calls the agent makes in this run |
| **Tool definitions** | `{{sample.tool_definitions}}` | Definitions of tools available to the agent |

4. Select **Next**.

## 4. Check agent input

1. Under **Configure agents**, select **Configure** for `contoso-travel-assistant`.
2. Verify **User prompt** is `{{item.query}}`. If different, enter this value and select **Save**.
3. Select **Next**.

## 5. Select Criteria

1. Keep only **TaskAdherence** and **TaskCompletion** from the initial evaluators.
   Remove unwanted chips using **×**. You may use **Remove all** for both
   **Quality** and **Safety** evaluators.
2. Add the workshop-specific custom evaluator registered in Lab 1:
   **[Contoso Travel Rubric](../docs/participant/contoso-travel-rubric.md)**.
3. Verify these **three** are selected:

| Evaluator | Checks |
|---|---|
| **TaskAdherence** | Compliance with instructions and the request |
| **TaskCompletion** | Whether required information was answered |
| **Contoso Travel Rubric** | Travel/expense policy compliance, necessary citations, correct tool use, scope, and safety boundaries |

Do not add ToolSelection / ToolInputAccuracy / ToolCallAccuracy.
Removing evaluators here does not change the agent's Guardrail.

## 6. Set inputs for each evaluator

Step 3's Field mapping supplies shared defaults. Open each evaluator chip,
set the following values, and select **Update** for each:

| Evaluator | Judge model | Query | Response |
|---|---|---|---|
| **TaskAdherence** | `gpt-5.5` | `{{item.query}}` | `{{sample.output_items}}` |
| **TaskCompletion** | `gpt-5.5` | `{{item.query}}` | `{{sample.output_text}}` |
| **Contoso Travel Rubric** | `gpt-5.5` | `{{item.query}}` | `{{sample.output_items}}` |

`sample.output_text` passes only the final answer; `sample.output_items` passes
the final answer and directly recorded tool calls.

Keep **TaskAdherence > Tool definitions** at `{{sample.tool_definitions}}`.
Leave fields not listed in the table at their defaults.
After **Update** for all three evaluators, select **Next**.

The retained [agent version](../docs/images/lab05-agent-version.png),
[dataset selection](../docs/images/lab05-data-selection.png), and
[TaskAdherence mapping](../docs/images/lab05-task-adherence-mapping.png) screenshots
are historical/illustrative, not English instructions or current-revision success evidence.

## 7. Run the Evaluation

1. In **Review**, enter `contoso-travel-portal-eval` for Evaluation name.
2. Verify one version of `contoso-travel-assistant`, the designated synthetic dataset,
   One time frequency, `gpt-5.5` Judge model, and the three evaluators above.
3. Select **Submit**.
4. Wait for Evaluation detail status **Completed** or **Partial**.
   Seven cases normally take several minutes. Do not resubmit while **In progress**.
5. Open results. **Partial** means some scoring could not complete; inspect **Error** below.

## 8. Read results

Open `contoso-travel-assistant` in the run list and inspect
**Overall metric results** and **Detailed metrics result**.

The former aggregates by evaluator; the latter shows per-question results.
Scroll the detailed table horizontally to compare question, answer, score, reason,
and **Error** at the far right. If a Conversation ID link appears, follow it to the conversation and tool calls.
Hover over truncated reasons briefly to read the full text.

For at least one row, compare the question, answer, policy, and scoring reason.
Model scoring is not necessarily correct; record disagreements between reasons and actual Traces.

| Result | Interpretation |
|---|---|
| **Pass / Fail** and reason | Identify improvements in answers and tool use |
| `content_filter` on an attack-text row | Record a safety block. Do not weaken Guardrail to pass it |
| **Error** such as `429` or timeout | Distinguish from scoring results and resolve the cause through [troubleshooting](../docs/participant/troubleshooting.md#evaluation-and-optimization) |

For rows requiring tools, open Conversation / Trace and inspect the tool selected by
`tool_search` / `call_tool` and the arguments/outputs of actual operations such as `createTripEstimate`.

**Completed / Partial does not guarantee every row was scored normally.** Inspect Error details.

## Completion checklist

- All 7 synthetic queries ran.
- Scored rows show pass/fail for each evaluator.
- Any safety blocks are distinguished from unresolved execution errors.
- Tool-required rows show selected tools and actual operation arguments/outputs.
- Evaluator reasons are available for Fail rows.

The next lab uses the same question dataset and registered **Contoso Travel Rubric**.

Details: [Run evaluations from the Microsoft Foundry portal](https://learn.microsoft.com/azure/foundry/how-to/evaluate-generative-ai-app).
